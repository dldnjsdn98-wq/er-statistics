# API 복구 및 보존 정책

기준 커밋: dd0847c96afe5a2cfbe1084a15526145f76fda5f. 기존 밝은 UI, 최대 7구간 추이, 저장 조건, 중립적인 공식 오류 분류를 보존한다.

## 요청 제어

공식 API 호출은 한 프로세스에서 직렬화한다. 호출 간 최소 1초, 대기열을 포함한 요청 기한 20초, 실제 응답 본문까지 최대 8초, 동시 대기 상한 16개다. 포화 요청은 REQUEST_QUEUE_FULL(503)과 재시도 안내를 반환한다. 자동 재시도는 하지 않는다.

HTTP 또는 JSON 429의 Retry-After 초·HTTP-date를 해석한다. 3,600초로 줄이지 않으며 공통 대기 상태 동안 후속 호출을 실행하지 않고 남은 시간을 반환한다. 헤더가 없거나 유효하지 않으면 60초로 안내한다. 이 값들은 앱의 방어 정책이며 공식 처리량 보장이 아니다. 다중 프로세스 배포 전에는 공유 제한기가 필요하다.

## 캐시와 상태

닉네임 성공 캐시는 60초·최대 500개이며 만료 항목을 제거한다. 같은 닉네임의 진행 중 조회를 공유한다. 실패는 최대 500개·5초 동안만 임시 보관해 반복 실패를 줄인다.

메타데이터의 진행 중 요청도 공유한다. 정상 캐시는 24시간, 장애 시 이전 목록은 최대 7일 사용하며 fresh/stale/unavailable과 lastUpdatedAt, retryAfterSeconds를 반환한다. 실패 후 최소 15초간 재조회하지 않는다. stats.coverage에는 metadataStatus와 해당 경고를 넣는다.

이전 전적은 저장소에 성공한 수집 이력이 있고 일시 장애·시간 초과·요청 제한인 경우에만 stale로 제공한다. 성공한 0경기 결과는 장애와 구분한다. UPSTREAM_NOT_FOUND/UPSTREAM_FORBIDDEN/인증·응답 형식 오류는 이전 닉네임 소유자의 결과로 대체하지 않는다. 404의 원인을 닉네임 부재로 단정하지 않는다.

coverage.retryAfterSeconds 및 retryAt은 재시도 안내다. UI는 KST 시각과 지표별 유효 표본을 표시하고, 새 검색·화면 해제 때 이전 브라우저 요청을 취소한다.

## 중복과 시각 정책

같은 배치의 (uid,gameId) 중복은 최초 유효 수치를 유지하면서 결측값만 보강한다. 시간·실험체·알려진 모드가 충돌하면 첫 관측을 유지하고 서로 다른 관측을 혼합하지 않는다. 이후 성공한 수집에서는 같은 식별 조건의 유효 수치를 갱신하고 새 null로 기존 값을 지우지 않는다.

경기마다 최초 시각 해석 정책을 저장한다. 빈 후속 응답은 기존 경기의 정책을 지우지 않는다. coverage.timestampPolicies는 현재 필터 결과의 모든 해석 정책을 포함하며, 기존 timestampPolicy는 호환용 대표값이다. 과거 행의 정책은 unknown으로 표시하고 추측으로 복원하지 않는다.

PostgreSQL 사용 시 배포 전에 db/001_init.sql 다음에 db/002_timestamp_policy.sql을 적용해야 한다. 새 마이그레이션은 열만 추가하며 기존 경기와 UID를 삭제하거나 연결하지 않는다.

## 최소 보존

메모리 저장은 최대 200명·사용자당 최근 10,000경기이며 24시간 미사용 시 사용자·경기·수집 이력을 함께 제거한다. 이 저장소는 영속 아카이브가 아니다.

PostgreSQL 경기 기록에는 임의 90일 자동 삭제를 추가하지 않는다. 90일은 공급자의 조회 범위다. 성공 수집 시 해당 UID의 30일 이전 동기화 로그만 정리하며 최신 성공 이력은 유지한다. 원본 응답, 키, 인증 헤더를 저장하지 않는다.

## 검증

새 테스트는 공통 cooldown, 긴 Retry-After, 대기열 포화·만료·복구, 본문 abort, 중복 수치 보강, 시각 정책, 메모리 용량·만료, 동시 조회 병합, 성공 이력 없는 오류, 실제 빈 결과와 장애, 메타데이터 복구를 모의 데이터로 검증한다.

이 변경을 준비한 채팅의 실행 환경은 사용할 수 없었다. GitHub Verify에서 테스트·타입 검사·빌드를 실행하도록 구성했으며 결과는 PR의 실제 체크를 확인해야 한다. 공식 플레이어·전적 API는 호출하지 않는다. PostgreSQL 테스트는 전용 로컬 테스트 DB의 임시 스키마에서 마이그레이션·upsert·롤백·로그 정리를 검증한다. 운영 DB 적용과 실제 닉네임 조회 성공은 별도 검증 대상이다.
